# 面试准备：技术 = 防事故

> 核心模型：每个技术选型，都是在防一类事故。
> 回答结构：**事故 → 方案 → 兜底**。

---

## 一、技术 → 事故 → 场景题

| 技术 | 防的事故 | 面试场景题 |
| --- | --- | --- |
| 事务 | 数据写一半，残缺 | “scan 写了但 approvals 失败怎么办？” |
| 队列 | 慢任务拖死请求 | “扫描 15 秒，用户等不了怎么办？” |
| 重试 + 退避 | 瞬时故障变永久失败 | “RPC 抖一下任务就失败了？” |
| 幂等 | 重复执行、重复扣款 | “同一个任务被消费两次？” |
| 缓存 | 数据库被打爆 | “1 万 QPS 查同一个地址？” |
| 写后删缓存 | 用户看到旧数据 | “刚撤销，页面还显示高风险？” |
| 限流 | 被打挂 | “有人刷接口怎么办？” |
| 超时 | 连接被占死 | “下游不响应，请求一直挂着？” |
| 健康检查 | 流量打到坏实例 | “一台机器挂了，负载均衡还转发？” |
| 优雅退出 | 请求被截断 | “发版时正在处理的请求？” |
| 大整数处理 | 金额/额度算错 | “无限授权显示成 0？” |
| 权限校验 | 越权访问 | “A 能看 B 的授权吗？” |

## 二、回答框架

**被问“为什么用 X”：**

> 因为会发生【事故】；X 能【怎么防】；代价是【成本】，可接受。

**被问“如果 X 坏了”：**

> 影响面是【哪些功能】；兜底是【降级/重试/标记】；监控是【看什么指标】。

**被问“量涨 10 倍”：**

> 先看瓶颈：DB 连接 → 外部 API 限流 → Worker 吞吐 → 单实例。
> 先监控再扩容，不盲目上 K8s。

## 三、本项目高频 10 问（要点）

1. **为什么从 Next 拆出 API？**
   Serverless 有时长上限、无长驻进程；队列/WS/定时任务做不了；前后端可独立发版扩容。

2. **为什么 Fastify？**
   async 原生、性能好、校验生态完整；团队用 NestJS 也能切换。

3. **为什么写库用事务？**
   1 条 scan + N 条 approvals 要么全成功要么全回滚；同一连接上 begin/commit。

4. **为什么扫描用队列？**
   外部调用慢且不稳；同步会超时、占连接；入队立即返回 jobId。

5. **任务重复消费怎么办？**
   幂等键（owner + 时间窗 / jobId 唯一约束）或先查后写。**当前未实现，是已知缺陷。**

6. **缓存一致性？**
   写后删 + TTL 兜底；不要先删后写。

7. **Redis 挂了？**
   缓存层 catch 降级查库；队列受影响，任务堆积；需监控。

8. **大整数为什么用字符串？**
   uint256 超 2^53，JSON number 丢精度；SQL 用 text，前端按字符串。

9. **撤销状态一致性？**
   signing → pending → confirmed/failed；必须 receipt success 才算成功。

10. **QPS 10 倍先崩哪？**
    连接池 → Etherscan 限流 → Worker 并发 → 单实例 API。

## 四、安全产品专属

| 产品风险 | 技术手段 |
| --- | --- |
| 显示过期授权 | 写后删缓存 |
| 误报“已撤销” | 交易 receipt 确认 |
| 漏扫代币 | 部分失败标记 `partial` |
| 额度算错 | 字符串大整数 |
| 接口被刷 | 限流 |

**原则：宁可不完整，也不能给假的安全感。**
